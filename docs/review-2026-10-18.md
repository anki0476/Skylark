# End-to-end review — October 18, 2026

Scope: submission, queue ownership, execution, tool validation, fault injection, observation delivery, verification, repairs, comparisons, reporting, exports, browser refresh, migration, and local recovery. This was a local code and behavior review using synthetic data and mocked inference. It was not a production security audit or a live NVIDIA evaluation.

## Findings and changes

| Area | Finding | Change and verification |
|---|---|---|
| Live comparison and benchmark admission | Decimal prices were multiplied by a floating-point constant; scheduling could raise a TypeError. Summing fractional request estimates also undercounted per-request rounding. | Use integer microdollars throughout preflight and round each maximum request upward. Mocked tests cover accepted and rejected comparisons and rejected benchmark batches. |
| Replay evidence | Replay checked business effects and the final verdict, but could accept changed agent observations, missing effect events, or inconsistent fault labels. | Recreate the complete tool transcript through the instrumented reservation context and compare normalized requests, effects, raw responses, guards, and delivered responses. Seven mutation cases are rejected. This validates the recorded tool transcript, not model decisions or authorship. |
| Regression source | A completed source status did not establish that its stored trace was intact. | Validate the source with deterministic replay before executing a new regression. A corrupted source fails before any tool runs. |
| Tool argument handling | A broad exception handler could relabel an internal execution/persistence ValueError as an argument mistake. Malformed JSON bypassed tool accounting. | Restrict argument-error handling to parsing/schema validation, journal rejected tool proposals, count them toward limits, and propagate internal failures without retrying the action. |
| Dashboard refresh | Every two seconds the browser downloaded full results, even on other screens; completed incidents and comparisons kept polling. | Fetch report summaries only on Results. Use non-overlapping scheduled polling, a ten-second idle interval, visibility pause, terminal event draining, and stop completed detail polling. Browser tests verify no background report fetch and no continuing terminal incident polls. |
| Database work | Scoped reports loaded and decoded every run, including authoritative state. Budget checks repeatedly loaded full usage payloads into Python. Queue and reconnect queries lacked suitable compound indexes. | Filter report scope in SQL, select only needed columns, read a consistent snapshot, aggregate money in SQL, and add queue/report/cursor indexes through migration 0002. Existing records survive migration. |
| Event streaming | Synchronous SQLite work ran on the async request loop; malformed or oversized reconnect cursors could reach database conversion. | Offload reads to threads, use narrow execution-state reads, and validate cursor bounds. Tests verify async progress during slow reads and visible 422 errors for invalid cursors. |
| Browser submission and errors | Losing a successful submission response could make a manual retry create another experiment. Validation arrays displayed as `[object Object]`. | Keep the submission identity for retries of the same form within the page session. Render validation locations and messages. Browser tests lose a real fixture response and verify the same run ID on retry. |
| Repair edge cases | Repeated version suffixes could exceed the agent-version bound; a model diagnosis containing JSON null could raise an internal TypeError. | Bound version names with a policy digest and validate diagnosis shape before accessing fields. Tests cover both cases. |

## Compatibility and operations

- Migration `0002_query_indexes` adds indexes and preserves run/event data; it does not reinterpret historical model results. The current local database was backed up before upgrade.
- Results use `skylark-report/2`. Dashboard responses are marked `summary`; downloaded/CLI reports are `full` and include per-run attempts and scoped `usage_attempts`. The `budget` object explicitly describes the whole local project allowance, including runs outside a selected comparison.
- Replay imports no customer adapter and performs no inference. Automatic exact replay remains limited to the built-in reservation environment. Redacted or incomplete evidence cannot establish an exact match.
- Batch preflight is an estimate. Each actual provider request still reserves allowance atomically; concurrent activity may cause later requests in an admitted batch to stop visibly. There is no provider-enforced billing guarantee.

## Remaining boundaries

The local single-worker architecture remains appropriate for this beta; no distributed queue or paid infrastructure was added. Reports still aggregate the requested history when opened. Multi-tenant isolation, hosted load/capacity tests, funded operations, and independent security review remain future gates.

Real Nebius access, eligible-model behavior, prices, token accounting, repair improvement, and held-out live results remain unverified until account setup. The offline checks cannot establish that the selected NVIDIA model recovers successfully.
