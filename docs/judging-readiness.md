# Judging readiness — October 22, 2026

The [official rules](https://nebiusglobalaihackathon.devpost.com/rules) use a pass/fail eligibility screen followed by four equally weighted criteria. This is an internal acceptance map, not a predicted score. Skylark is aimed at the **Best Apps and Agents** track: a working local application in which NVIDIA Nemotron makes live tool decisions through Nebius Token Factory.

| Criterion | Evidence a judge should be able to see | Current state | Next gate |
|---|---|---|---|
| Technological implementation | A fresh Nemotron call, injected tool fault, committed simulator state, agent-visible response, independent verdict, cost, and replayable event trace | Working local pipeline; 12-run live development pack and an exploratory `/5` freshness comparison recorded. The [limited live held-out protocol](live-held-out-2026-10-22.md) completed 12/12 scheduled attempts: 11 completed, one failed before reaching its fault. All 11 completed traces replay. Original fault cases passed 1/3; guarded cases passed 2/3 with one inconclusive. Six controls passed | Ask another person to reproduce a scoped export and inspect the inconclusive trace; do not extrapolate from one variant per fault |
| Design | A new user can move from task and fault selection to an incident, inspect what happened, review a specific repair, compare fresh runs, and export evidence | Workbench, comparison, results, settings, responsive layout, protocol-scoped Results, 20 offline browser checks, and a same-machine clean archive install passed | Have an independent user follow the [review handoff](independent-review.md); fix any blockers before recording the demo |
| Potential impact | A specific audience recognizes a costly failure and sees a test they can apply to their own agent | Target audience: teams building agents that call transactional or eventually consistent tools. The reservation example shows how a timeout can hide a committed booking and a retry can duplicate it | Explain the transfer to real workflows without claiming that synthetic results prove production safety; obtain external user feedback if available |
| Quality of the idea | The product distinguishes true tool state, a damaged response, the agent's belief, and a reviewed change's effect | The event journal, immutable snapshots, independent safety/completion/reporting checks, versioned verifier, and runtime-vs-prompt repair distinction demonstrate this | Show one counterexample where a naive pass was misleading, then show the versioned check and a fresh guarded comparison |

The eligibility gate is as important as the four scores: the submission needs a public licensed repository, a working demo/test-build URL, a public YouTube video under three minutes, and free unrestricted judge access through December 15. The current trial ends before judging and is set to stop usage afterward. A credit or hosting arrangement that covers that period remains an external dependency. The local archive is prepared but is not published.

The rules accept a working demo, hosted application, **or test build** and encourage Nebius hosting without requiring it for Best Apps and Agents. Skylark already has a FastAPI backend and SQLite persistence. For this submission, prioritize a reliable local install and complete incident-to-repair experience over adding multi-user authentication or a hosted database. Add those only if a later hosting plan needs separate user data and access control.

Do not present fixtures as model evidence, a one-pair result as a reliability rate, or a runtime guard as model learning. Show both successful and failed runs, and retain denominator, fault coverage, uncertainty, latency, and cost. The small held-out option is explicitly one fixed variant per fault family and one trial; it does not replace the 78-run target.
